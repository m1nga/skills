# 节目类型与结构

每种类型共守三条:结论前置(听的人随时会停)、路标句开路(耳朵没有滚动条)、
文体过 spoken-chinese.md(写稿前必读)。段落 ≤150 字;一个带标签的节目段
(播放器里的一个块)可以含多段。

## 对比(两份及以上文档)

1. **开场**(~20 秒)— 一句话说清今天听的是哪几份,各自一句话定位(谁写的、关于什么、立场是什么)。
2. **先说结论**(~40 秒)— 最大的共识一句话,最大的分歧一句话,以及"如果只记住一件事,记这个"。
3. **第一份:〈口语化的文档名〉** — 3 到 5 个要点,按重要性排,不按原文顺序。
4. **第二份:〈口语化的文档名〉** — 同上,刻意呼应第一份的维度,方便耳朵对齐。
5. **相同点** — 2 到 4 条,合并同类项。
6. **不同点** — 按问题维度组织,不按文档组织:"在〈什么问题〉上,第一份认为……第二份认为……这条关键不关键,为什么。"
7. **收尾**(~20 秒)— 一句话判决:合起来告诉你什么,或下一步该做什么。

三份以上同结构,对比仍按问题维度,绝不两两穷举(穷举听不下去)。

## 总结(一份文档,或一段工作)

1. **开场** — 这是什么、哪来的、为什么现在值得听。
2. **先说结论** — 全文最重要的一件事;如果只记一句,记哪句。
3. **重点** — 三到五个,每个先给判断再给依据;按对 Ming 决策的重要性排,不按原文顺序。
4. **边角但有用** — 0 到 2 条容易被漏掉的细节,可省。
5. **收尾** — 这份东西接下来该被怎么用。

## 观点(对一段工作给出更多视角与思考)

1. **开场** — 现状一句话:这是什么工作,做到哪一步了。
2. **总判** — 当前这个工作最需要被说出来的一句话。
3. **观点** — 三到六个。每个的骨架:观点本身 → 为什么(依据或类比)→ 对手头决定的影响。
   **至少一个唱反调的**——最强反方案例必须在场。观点要可执行、可反驳,
   禁止"多喝热水"式的正确废话。
4. **收尾** — 如果只采纳一条,采纳哪条,为什么。

## 潜在问题(风险盘点)

1. **开场** — 扫的是什么。
2. **总体判断** — 一句话:整体稳不稳。
3. **问题清单** — 按严重度从高到低。每个:问题是什么 → 什么情况下会真的发生 →
   发生了多严重 → 现在能做什么。**"证据确凿"和"我推测"必须分开说**,
   绝不把猜测念成事实。
4. **收尾** — 哪几条今晚就该处理,哪几条可以睡个好觉。

## 多素材合集(收件箱里不止一件互不相关的素材时)

- 开场先报节目单:今天有几件、各是什么、大约多长(素材停车超过一周的,报龄)。
- 每件自成一组段落,内部用它自己类型的结构,可适度精简;组间用路标句切换
  ("第一件说完了,第二件是……")。
- **播放器里的分组只有两个手段**:给每段的 JSON 加 `item` 字段(如
  `"item": "第二件:蓝湾报告"`,同值的连续段落归一组,播放器会渲染组头),
  并且段落 label 尽量自带件号("第二件·先说结论")——别指望听众用眼睛找分界。
- 每件按自己的 length;**合计超过 20 分钟就不要硬塞**——按 SKILL.md 的优先级取舍,
  播不下的留在收件箱,节目单里说明"箱里还有几件"。

## 时长换算

中文口语约 **260 字/分钟**(云希常速)。默认 5–6 分钟 ≈ 1300–1600 字;
"15 分钟" ≈ 3900 字;"短版" 90 秒 ≈ 350 字。字数指听稿正文,不含标签。
单期上限 20 分钟(约 5200 字)——超过就分期,取舍规则在 SKILL.md。
超过 8 分钟的节目,把内容切成更多小段落,并在中途加一次"到这里说完了前一半"
式的锚点——长节目里听众更容易走神后找不回位置。
