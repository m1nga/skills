# Repeated research without repeated bulk reading

Use the task's existing state, source archive, reader and acceptance checks. The following route can be wired into a host's existing instruction entry point; it requires no scheduled process.

1. **Freeze the outcome.** Identify the prior result, current question, source scope and required deliverable. Distinguish a fresh source fetch from a replay of saved snapshots. Record partial/unknown coverage and evidence still missing.
2. **Locate the cost.** Measure the largest candidate payload before loading it. Separate archive size on disk, selected source bytes, bytes actually exposed to the model and provider tokens. A large archive is not automatically the old workflow's model input.
3. **Compare the whole scope in code.** Prefer the project's existing comparison. Otherwise use `scripts/source_delta.py` with stable IDs, meaningful revisions and recoverable references. Consume every relevant page. An absent ID in a partial scan remains unresolved, not deleted. Include changed content, permissions and relevant status, not only titles.
4. **Read what the decision needs.** Reuse a prior semantic review only when its source revision and required coverage match. A prior index entry is not a reviewed body. Read all relevant new/changed sources and any unchanged source whose content was never reviewed or whose freshness matters. Keep original post claims, author/reader comments and the agent's interpretation separate. Retain missing modality and truncation limits.
5. **Deliver and accept.** Use the original output and checks: source identities, supported findings, useful next action, uncertainty and required failure recovery. Compare the new result against those requirements before advancing the reviewed baseline. Store the exact reviewed IDs/revisions and unresolved items in the existing task record.

## RedBot adapter

Use the authorized account or named backup. A web search over saved local text and an account synchronization request have different dependencies; one being fast does not establish the other's health. A failed connection must not trigger repeated sign-ins or a new full scan when saved evidence can answer the current task.

When the RedBot skill is installed, reuse its actual `scripts/read_library.py` entry point for a bounded shortlist and selected ID reads. Invoke it through the resolved installed path. It is a lexical reader, not proof of semantic relevance; vary the query or inspect the changed candidates when needed. A `truncated` response requires recovery of the necessary original material. Do not reimplement its comment sanitization or copy credentials into the comparison.

For a paired trial, both paths use the same source snapshots, relevant bodies and comment sample. The baseline uses the real existing route, with reasonable field filtering; never inflate it with raw media URLs or irrelevant files to make savings look larger. The optimized path changes selection/transfer first. Keep missing evidence identical and mark a historical replay honestly.

## Keep the improvement usable

Retain the executable commands and source locations in the private task record. Publish only reusable instructions, code and sanitized measurements. Installation, observed trigger, actual execution and outcome acceptance are separate checks. A saved rule cannot guarantee that already-running agents have adopted it; apply it on their next authorized natural entry without waking them.

Reuse the proven route for later runs. Reopen measurement when meaningful changes or failures could invalidate it. If quality fails, restore the omitted source and account for that extra read and rework before claiming savings.
