# Open a perspective, not a conclusion

Use these original examples to choose a few different lenses. They are not facts about the user, a diagnostic checklist, or questions everyone must answer. A broad or philosophical question is welcome when it opens something meaningful; it need not justify itself through an immediate work output.

| Lens | A possible opening | What to avoid |
| --- | --- | --- |
| Original purpose | “What drew you to making this? Which part still matters, and which part could you let change?” | Assuming the first reason is sacred or that the user has lost it |
| Enough | “What would make a small version feel worth having made, even if it never grew?” | Telling them to abandon ambition or accept less |
| The actual constraint | “If the integration worked tomorrow, what would you still be unsure about?” | Treating a documented technical failure as an emotional block |
| Competing explanations | “What have you seen that suggests the hard part is the technology? What might point to a different explanation?” | A forced choice between technology and mindset |
| Chosen tradeoff | “Which part are you protecting by keeping this complicated—and is that tradeoff still yours to choose?” | Assuming complexity is waste or that the answer is simplification |
| Another witness | “What might someone who never posts still value here?” | Replacing the user's audience with an imaginary authoritative user |
| An unexpected measure | “If people used this less because it helped them finish sooner, what would success mean?” | Treating one philosophical framing as the correct business strategy |
| A strange connection | “If this project were a place you could visit, where would you want to linger?” | Randomness with no invitation to explore it |
| A sourced old thread | “You mentioned [actual idea] in [actual source]. I don't know whether you tried it since. Does any part of it still interest you?” | Saying they never started because no progress note exists |

For example, a maker is polishing onboarding while saying visitors should feel welcome without participating. Three distinct questions could explore what welcome meant at the start, whether silent browsing fulfills that promise, and what would remain unresolved if signup were flawless. These are possibilities, not proof the maker is polishing the wrong thing.

After an answer, reflect its particular wording and relate it to known context. If the person says “I don't want participation to feel like homework”, a synthesis can distinguish that value from a proposed feature such as removing reactions. Ask permission before treating the feature as a chosen direction. A small reflection can end with that distinction alone.

If the person wants an unrelated break, let it stay unrelated. For example: “Would a perfect copy of a place you remember feel like the same place?” or “What would a lost-property office do with an unspoken sentence?” Do not smuggle a work assignment into a requested diversion.
